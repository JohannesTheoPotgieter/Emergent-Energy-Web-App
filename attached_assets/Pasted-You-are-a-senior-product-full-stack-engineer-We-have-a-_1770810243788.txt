========================================================
PART 2 — WRITE-BACK TO EXCEL (WORKBOOK/SHEET/CELL)
========================================================
We need the ability to push specific values back to a specific Excel file, sheet, and cell (or range).

This is high-risk. Implement it safely.

A) Supported writeback modes (MVP)
1) “Manual push” only (no automatic sync).
2) User selects:
   - Target workbook (preconfigured path or uploaded file)
   - Target sheet name
   - Target cell (A1) or named range
   - Value to write (picked from allowed fields)
3) Confirm dialog shows:
   - current cell value (read it first)
   - new value
   - user + timestamp
   - scenario/project context

B) Writeback mapping templates
Create a “Writeback Mappings” admin screen where we define:
- mapping_id
- name (e.g., “Update Project Tracker: Commissioning Date”)
- workbook reference (stored path or storage key)
- sheet name
- cell/range
- source field (e.g., project.forecast_commissioning_date)
- transform (date format / number / text)
- validation rule (e.g., must be a date)
- allowed roles (who can push)

Then in the project screen, users choose a mapping and press “Push to Excel”.

C) Audit + rollback
Log every writeback:
- writeback_id
- mapping_id
- workbook, sheet, cell
- previous_value
- new_value
- user_id
- timestamp
- project_id
- success/failure + error message

Rollback:
- “Revert” button to write back the previous_value.

D) Technical constraints
- This must work for .xlsx and .xlsm.
- Preserve macros: do NOT destroy the .xlsm file. Use a library that can edit cell values while keeping VBA content intact.
  - If using Python: openpyxl can read/write xlsx; xlsm support exists but must preserve VBA using keep_vba=True.
  - If Node: many libs break macros; verify before shipping.
- Concurrency:
  - Implement a file lock or queue so two people cannot write to the same workbook simultaneously.
- Validation:
  - Reject invalid cell addresses and sheet names.
  - Reject writing formulas unless explicitly allowed.

E) Security
- Only Admin can configure mappings.
- Only permitted roles can run a mapping.
- Workbook storage must be controlled (no arbitrary filesystem write).
