BUSINESS RULES TO ENFORCE FOR COS
Use existing approved company logic wherever it already matches these rules.

Definitions:
A. COS Planned
- App data only
- Includes relevant COS lines in scope for the selected filters / period from the application tracker/state
- Planned is not QB
- Planned is not Budget
- Planned is not inferred from QB

B. COS Committed
- App data only
- Includes lines where an invoice exists on the app/tracker line
- But the relevant financial recognition state is not yet realised
- This usually corresponds to future / deferred / red-state logic in the tracker, but use the underlying status/date fields, not colour alone

C. COS Realised
- App data only
- Includes lines that meet the existing approved COS realised rule in the tracker/app
- Preserve the company rule that COS is only realised when an invoice is captured under actuals
- Realised must not borrow from QB actuals

D. QuickBooks COS
- QB data only
- Never used as fallback for Planned, Committed, or Realised

E. Budget
- Budget only
- Never used as fallback for App or QB rows

F. Variance metrics
- These may compare the above sources, but the source rows themselves must stay pure

Also preserve:
- an invoice without a PO is a red flag
- payment receipt/payment date drives cashflow logic, not COS realisation, unless an existing approved rule explicitly says otherwise in current business logic

If there is any conflict between current code and these rules, stop and report the exact conflict before changing the calculation path.
