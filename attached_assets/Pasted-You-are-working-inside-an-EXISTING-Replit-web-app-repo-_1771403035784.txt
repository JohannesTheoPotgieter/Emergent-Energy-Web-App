Core design principles

G) Warning Engine (bright red only, no blocks)
Warnings are objects with owners, due dates, severity, and audit.

WarningEvent audit:
- warning_id, event_type, note, actor_user_id, created_at

Warning rules (minimum)
1) Task overdue:
- due_date < today AND status != COMPLETE → MED (or HIGH if phase is Commissioning/Handover)
2) Milestone due soon risk:
- plan milestone due within 7 days AND linked deliverables not QC APPROVED (or not COMPLETE) → HIGH
3) Missing evidence:
- quality item approved OR deliverable QC APPROVED but no evidence/approved_file_refs → HIGH
4) Orphan task:
- task missing link to plan/deliverable/quality after 24h → MED (owner: Eng Program Manager)
5) Invalid dates:
- end < start → HIGH
6) Folder mismatch:
- file uploaded outside configured project folder map for HO-critical evidence → HIGH
7) Review stuck:
- status=NEEDS APPROVAL older than 2 working days → MED; escalate if milestone due soon

Acknowledgement (not a block)
- When someone completes a plan milestone with HIGH warnings open:
  - show a bright red modal listing warnings
  - allow “Proceed anyway”
  - log acknowledgement event (who/when + optional reason)
  - warnings remain open until fixed/accepted risk
