TASK
Add a read-only HTTP endpoint /api/ops-dashboard to our existing web app that returns a JSON snapshot of operational data sourced from the claude_views.* schema. This will be consumed by external dashboards / agents — never by an unauthenticated browser.

CONSTRAINTS
- Use the existing Postgres connection. The endpoint SHOULD use the claude_readonly role's connection string — store as Replit Secret CLAUDE_RO_DATABASE_URL. Do not use neondb_owner.
- Authenticate every request with a Bearer token compared against Replit Secret OPS_DASHBOARD_API_KEY. Generate a 32-byte CSPRNG key (openssl rand -hex 32). Reject any request without a matching token: 401, no body other than {"error":"unauthorized"}.
- CORS: respond to OPTIONS with Access-Control-Allow-Origin: * (acceptable because we use Bearer auth, not cookies), Access-Control-Allow-Methods: GET,OPTIONS, Access-Control-Allow-Headers: Authorization,Content-Type. The endpoint must be callable from any origin including iframe sandboxes.
- Endpoint is read-only. No write paths. No SQL injection surface — use parameterised queries only.
- Cache the response in-memory for 60 seconds (simple TTL cache keyed on nothing — single payload). Return Cache-Control: private, max-age=60.
- Set Content-Type: application/json; charset=utf-8.
- Log every request: timestamp, source IP, user-agent, status. No request body to log (it's a GET).
- Add rate limit: max 60 requests/minute per IP. Above: 429.

ENDPOINT
GET /api/ops-dashboard
