TASK A: Add invoice-number-only counterparty/type inference into the CURRENT smart import
CONTEXT
- In Expenditure Breakdown imports, we want to classify each line as:
  - counterparty_type: INSTALLER or SUPPLIER (or OTHER)
- We want to do this using invoice_number ONLY as the signal when possible.
- Because invoice numbers may not always be unique or pattern-rich, implement confidence scoring and require user confirmation when uncertain.
- When user confirms, the system should “learn” the pattern so next time it auto-classifies.

INVOICE NUMBER NORMALIZATION
Create a deterministic normalization function:
- trim
- uppercase
- collapse whitespace
- replace multiple separators with single (e.g. "--" -> "-")
- keep digits/letters and common separators (- / _)
Store both raw and normalized.

PATTERN GENERATION + MATCHING LOGIC
For every expenditure line with invoice_number:
1) Normalize invoice number.
2) Compute quick “token shape” features:
   - prefix letters before first digit
   - presence of year token (20xx or yy)
   - separator style (- / _ / none)
   - length buckets
   - pattern signature e.g. "AAA-YYYY-NNNN"
3) Attempt to match against InvoicePatternRule in this order:
   a) Exact PREFIX matches
   b) REGEX matches
   c) TOKEN_SHAPE matches
4) Compute confidence_score:
   - base from rule.confidence_weight
   - boost if rule.times_confirmed high
   - reduce if rule has many user overrides
   - if multiple conflicting matches, reduce and mark as uncertain

DECISION RULES
- If confidence_score >= 85: auto-apply inferred_type (and inferred counterparty if rule specifies it)
- If 50 <= confidence_score < 85: require user confirmation in Import Review UI (“We think this is INSTALLER. Confirm?”)
- If < 50: mark as UNRESOLVED and require user to select type (and optionally counterparty)

LEARNING LOOP (MANDATORY)
When a user confirms or overrides:
- If user confirms inferred_type: increment times_confirmed; set last_confirmed_at
- If user overrides:
  - log override
  - reduce confidence_weight OR increment an overrides counter
- If no rule existed:
  - create a new rule using best available pattern:
    - if invoice has stable prefix letters+separator, create PREFIX rule
    - else create TOKEN_SHAPE rule
  - store the example
- Always store InvoicePatternMatch with outcome and confidence.
