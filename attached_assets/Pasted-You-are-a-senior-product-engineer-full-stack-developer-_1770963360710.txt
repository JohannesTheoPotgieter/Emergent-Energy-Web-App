3) EXPECTED % COMPLETE LOGIC (AUTO-CALCULATED)
========================================================
Expected % is time-based and must track days.

Rule (time-based):
- If today < planned_start_date => expected = 0%
- If today > planned_end_date => expected = 100%
- Else expected = (days elapsed from planned_start to today) / (total planned duration days) * 100
- Round rules: display to whole number % (or 1 decimal if desired)

Important:
- Expected % should NOT be manually editable.
- Expected % must be calculated per task using planned dates.
- Parent tasks show rollup expected % based on children (see rollups below).

========================================================
4) ROLLUPS (PARENT ↔ SUBTASKS)
========================================================
We must support:
- High-level tasks (e.g., “1 Project Initiation”)
- Subtasks (1.1, 1.2, etc.) nested under parent
- Rollups must work reliably.

Rollup rules:
A) Parent planned_start_date = MIN(child planned_start_date)
B) Parent planned_end_date = MAX(child planned_end_date)
C) Parent planned_duration_days derived from parent planned dates

D) Parent actual_start_date = MIN(child actual_start_date where exists)
E) Parent actual_end_date = MAX(child actual_end_date where exists)
F) Parent actual_duration_days derived

G) Parent percent_complete rollup:
- Default: weighted by child planned_duration_days (or equally weighted if duration missing)
- percent_complete_parent = SUM(child % * weight) / SUM(weights)

H) Parent expected_percent_complete rollup:
- same rollup method as percent_complete (duration-weighted)

If some tasks have no children, they behave as normal leaf tasks.
