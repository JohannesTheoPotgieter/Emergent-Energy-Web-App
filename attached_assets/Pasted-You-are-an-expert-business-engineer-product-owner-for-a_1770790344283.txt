FEATURE SET 2 — CASHFLOW PLANNING + FORECASTING (WEEKLY)
Goal: not only show actuals, but forecast future cash by week and show if we go negative.

A) Cashflow Inputs
Actuals (from imported data):
- Inflows actual = ProgramInflows where PaymentRecievedDate in week
- Outflows actual = ProgramExpense where ExpensePaymentDate in week

Forecasts:
- Inflow forecast:
  - If milestone invoice raised date exists but payment date missing, forecast receipt = invoiceRaisedDate + payment_terms_days (configurable by client/funder)
  - If neither date exists, forecast using milestone “planned date” derived from ProgramPlan (e.g., commissioning/handover tasks) OR manually entered milestone forecast date
- Outflow forecast:
  - If invoice date exists but payment date missing, forecast payment = invoiceDate + supplier_terms_days (configurable by supplier/category)
  - If neither exists, forecast based on planned procurement curve: allocate remaining forecast COS spend across weeks between construction start and commissioning (simple linear or weighted curve)
- Operational OPEX budget:
  - monthly budget inputs allocated across weeks in each month

B) Cashflow Outputs (Weekly)
For each week:
- Opening balance (manual starting point + rolling)
- Actual inflows/outflows
- Forecast inflows/outflows
- Closing balance (actual + forecast)
- “Minimum balance” alert for any week < threshold
- “Runway” (weeks until negative, if forecast stays)

UI:
- Toggle: Actual only / Actual + Forecast
- Toggle: Conservative vs Aggressive assumptions (payment terms days)
- Drilldown per week: list forecast items with confidence level:
  - High: invoice exists
  - Medium: milestone exists, planned date exists
  - Low: allocation curve based

Testing:
- Unit tests for forecast logic with sample milestones/invoices
- Parity-like tests ensuring actuals match Excel, and forecast follows the defined rules
