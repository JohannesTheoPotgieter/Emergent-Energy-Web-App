SCOPE C — OUTLOOK INTEGRATION (MICROSOFT GRAPH)
Implement Outlook integration using Microsoft Graph.

C1) Auth + Connection
- Add an OAuth connect flow from Settings.

- Add disconnect (revokes local tokens and clears connection state).

C2) Calendar Read (Meetings Display)
- Show Outlook meetings inside Today and Week views.
- Meetings/events are read-only in My Tool. Do not allow editing/deleting Outlook meetings from the app.
- Fetch events for the relevant date range (today and current week).
- Handle recurring events safely (display only).

C3) Time Blocks Writeback (Create/Update/Delete)
- Time blocks are created/edited/deleted inside My Tool.
- Time blocks must sync to Outlook as calendar events.
- Do NOT edit meetings created by humans. Only edit/delete events created by My Tool.
- Mark My Tool events in Outlook using ONE of these approaches:
  - Preferred: a dedicated calendar named “EE – My Tool Blocks”.
  - Fallback: a category named “My Tool”.
- Store outlookEventId (and calendarId if applicable) on each time block row in the database.
- Prevent duplicates using idempotency keys (if the same create request is retried, it must not create a second event).

C4) Timezones
- Store UTC in DB.
- Convert correctly to Africa/Johannesburg for display.
- Ensure Graph calls use correct timezone handling (explicit timezone header OR server-side conversion to UTC).

C5) Sync reliability
- Start with range-based fetch on load.
- Then implement incremental sync using Graph delta queries where possible.
- If delta sync is implemented, store the delta cursor per user.

C6) Graph Permissions
Calendar:
- Calendars.Read (required)
- Calendars.ReadWrite (required for time blocks)
Mail:
- Mail.Send (required only for sending approvals)
