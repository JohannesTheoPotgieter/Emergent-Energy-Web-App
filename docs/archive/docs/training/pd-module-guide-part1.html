1. What is the PD Module?

The Project Development (PD) module is where the PD team's work becomes visible to the rest of the company. It is not a replacement for Pipedrive — the PD team continues using Pipedrive for their CRM/sales pipeline.

Instead, this module is where:

  • Engineers see their feasibility work assignments and track technical assessments
  • Project Managers see what's approaching handover and review readiness
  • Leadership (COO/MD) gets pipeline visibility for planning, forecasting, and board reporting
  • PD team manages the handover workflow to move projects into execution
ℹ️
Think of it this way Pipedrive = where PD tracks their sales pipeline internally.
This module = where everyone else in the company sees PD's work and where formal handovers happen.

The Big Picture Flow

Client Inquiry PD Creates Engineering Ready for PM Reviews (from Pipedrive) ---> PD Ticket ---> Tasks Spawn ---> Handover ---> & Accepts | | | | | External CRM Internal Ticket Work Gets Done Checklist Met Project Goes (not this app) (this module) (ENG module) (this module) to Execution

4.2 Dashboard Sections Explained

Metric Cards (Top Row)

Six cards showing ticket counts. Click any card to jump to the full ticket list.

  • Total — Every PD ticket ever created
  • Active — Tickets in "Draft" or "In Progress" status
  • Overdue — Past their due date and not completed/cancelled
  • Due This Week — Due within the next 7 days
  • On Hold — Paused tickets needing unblocking
  • Completed — Finished tickets

Pipeline Summary

Shows how tickets flow through the stages. The Pipeline Value badge (top-right) shows the total estimated project value of all active tickets that have financial estimates.

View Toggle: Table vs Kanban

You can switch between two views:

  • Table view — A flat list of recent tickets (default)
  • Kanban view — A board with columns: New → In Progress → Under Review → Ready for Handover → Handed Over
✅
Tip Use Kanban view in team standups to quickly see where every ticket sits in the pipeline.
